# Skill Chaining 技能串联协调器

## 技能注册表参考

详见：[技能注册表](./references/skill-registry.json)

---

## Phase 1：任务分解

**输入**：用户的复合推理任务描述（自然语言字符串）

**输出**：子任务列表，每项包含 `{ task_id, skill_name, input, depends_on }`

### 步骤

1. **提取任务关键词**：从用户描述中识别动词和名词短语，匹配推理动作
2. **查语义字典匹配对应技能**：
   - 加载 `skill-registry.json` 中的关键词映射
   - 对每个提取的关键词，遍历技能关键词列表，选择匹配度最高的技能
   - 匹配度计算：命中关键词数 / 技能关键词总数
3. **确定依赖顺序**：
   - 识别哪些子任务的输出是后续子任务的输入（数据流依赖）
   - 构建依赖关系：`depends_on` 为前置 `task_id` 列表（无依赖时为空列表 `[]`）
4. **分配 task_id**：按执行顺序赋予自增整数 ID（从 1 开始）

**判断节点**：

- 匹配到 1 个技能且任务可完成 → 直接调用该技能，跳过 Phase 2 和 Phase 3，直接执行
- 匹配到 2-3 个技能 → 构建线性串联计划，进入 Phase 2
- 匹配到 4 个及以上技能 → 构建 DAG 执行计划（有向无环图），进入 Phase 2

**失败处理**：

- 无法匹配任何技能（所有关键词匹配度 = 0）→ 提示："无法识别任务类型，请使用更明确的描述或参考技能关键词列表"，停止执行

---

## Phase 2：语义关联验证

**输入**：子任务列表 + 语义字典（来自 `semantic-dictionary` 技能）

**输出**：验证后的执行计划，每项附加 `semantic_confidence` 字段

### 步骤

1. **技能名称语义验证**：对每个子任务，通过 `semantic-dictionary` 技能的 Phase 2（语义匹配）验证 `skill_name` 的合法性
   - 调用：`semantic-dictionary.Phase2(query=skill_name, dict=skill_registry_dict)`
   - 获取匹配结果中最高 `score` 作为 `semantic_confidence`
2. **串联可行性计算**：
   - 检查相邻技能的输出类型（`output_type`）是否与下一技能的输入类型（`input_type`）兼容
   - 兼容性规则（来自 `skill-registry.json`）：完全匹配 → 可行性分数 1.0；类型相关 → 0.7；类型不匹配 → 0.3
3. **更新执行计划**：为每个子任务记录 `semantic_confidence` 和 `chain_feasibility`

**判断节点**：

- 所有子任务 `semantic_confidence` ≥ 0.7 → 执行计划验证通过，进入 Phase 3
- 存在 `semantic_confidence` 在 [0.5, 0.7) 之间的子任务 → 暂停执行，列出可疑子任务，请求用户确认后继续
- 存在 `semantic_confidence` < 0.5 的子任务 → 验证失败，输出具体失败原因："技能 `{skill_name}` 无法在语义字典中匹配，建议替换为：`{候选技能列表}`"，停止执行

---

## Phase 3：串联执行

**输入**：验证后的执行计划（含依赖关系图）

**输出**：每个技能的执行结果列表 + 中间状态快照

### 步骤

1. **按依赖顺序执行**：
   - 使用拓扑排序确定执行顺序（优先处理无前置依赖的任务）
   - 并行执行所有 `depends_on = []` 的任务
   - 串行执行有依赖的任务（确保前置任务已完成）
2. **每步验证输出**：
   - 检查技能返回结果是否包含必要字段（非空、类型正确）
   - 若输出符合预期 `output_type` → 标记该步骤状态为 `SUCCESS`
   - 若输出为空或类型错误 → 标记为 `FAILED`，触发失败处理
3. **传递上下文到下一技能**：
   - 将上一步的输出结果注入到下一步的 `input` 字段
   - 保存每步执行快照（`task_id`、`status`、`output`、`timestamp`）

**失败处理**：

- 单步骤执行失败 → 记录失败原因（错误类型 + 错误消息），尝试回退到上一步（重新执行上一步并尝试不同参数）
- 连续两步（步骤 N 和步骤 N+1）均失败 → 中止整个流水线，输出失败报告："流水线在步骤 `{task_id}` 和 `{task_id+1}` 连续失败，中止执行，请检查输入数据"

---

## Phase 4：结果综合

**输入**：所有技能执行结果（状态为 `SUCCESS` 或 `FAILED` 的列表）

**输出**：综合结论 + 推理路径图（文本表示）

### 步骤

1. **整合各步输出**：
   - 收集所有状态为 `SUCCESS` 的结果，按执行顺序排列
   - 统计执行统计信息：总步骤数、成功步骤数、失败步骤数
2. **检查一致性**：
   - 检测跨步骤的矛盾结论（如 Phase A 结论为 TRUE，Phase B 引用同一命题结论为 FALSE）
   - 矛盾检测规则：相同实体、相反结论 → 标记为 `[一致性冲突]`，列出冲突详情
3. **生成推理路径图**（文本格式）：
   ```
   任务 1 [skill_name] → 任务 2 [skill_name] → 任务 3 [skill_name]
         ↓                      ↓
       [输出摘要]            [输出摘要]
   ```
4. **生成最终结论**：整合所有成功步骤的核心输出，形成一致性结论

**判断节点**：

- 所有步骤成功（`FAILED` 步骤数 = 0）→ 输出完整综合结论
- 部分步骤失败（0 < `FAILED` 步骤数 < 总步骤数）→ 标注 `[不完整]`，输出已完成部分的结论，并注明缺失步骤及影响范围
- 全部步骤失败（`SUCCESS` 步骤数 = 0）→ 输出 `[执行失败]`，返回 Phase 1 重新分解任务

**输出示例**：

```
执行状态：✅ 完整（4/4 步骤成功）

推理路径图：
  任务1 [semantic-dictionary] → 任务2 [analyze] → 任务3 [judge] → 任务4 [decision-making]
        ↓                              ↓                  ↓
  语义匹配结果(0.92)           相关性分析报告          判断结论:TRUE         最优方案:A

综合结论：
  基于语义字典匹配（置信度 0.92）→ 数据特征分析（相关性 r=0.78）→
  阈值判断（TRUE，置信度 0.85）→ 多准则决策（方案A最优，得分 87.3）

一致性检查：✅ 无冲突
```
